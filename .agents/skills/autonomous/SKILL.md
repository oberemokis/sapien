# Автономная работа

Задачи идут одна за другой и доводятся до слияния без вопросов к человеку. Этап это milestone «Этап N. …» на GitHub (`gh api repos/{owner}/{repo}/milestones --jq '.[].title'`), текущий этап открытый с наименьшим N.

1. Вопросы этапа. Собери вопросы из блоков «Что решить до кода» всех задач этапа и из «Открытых вопросов» их эпиков и реши их сам. Ответ с причиной записывается комментарием в задачу, к которой относится вопрос, и повторяется в пул-реквесте этой задачи. Человек правит ответы после слияния своими задачами.
2. Выбор. Следующая задача этапа та, у которой закрыты все задачи из строки «Зависит от».
3. Работа по шагам скилла `branches`. Задача с отвеченными вопросами считается прошедшей допрос: условия допроса из скилла `core` (больше трёх файлов, несколько слоёв) срабатывают здесь почти на каждой задаче и сами остановку не дают.
4. Проверка вживую. Интерфейс проверяется в `pnpm dev:web` в браузере по пунктам блока «Проверка», скриншоты идут в пул-реквест рядом с образцом. Образец лежит в `docs/plan/design/` корня репозитория: папка вне git, и в worktree её нет. Окно Tauri и команды Rust проверяет человек.
5. Пул-реквест пушишь и открываешь сам. В описании, кроме `Closes`: решения, принятые без человека, скриншоты и список того, что проверить человеку в окне.
6. Сливаешь сам, при зелёном CI. Ревью идёт после слияния, правки по нему приходят своими задачами и пул-реквестами.

Решения, которые меняют формат сохранённых данных или формат команд Rust, добавляют зависимость или выходят за блок «Что нужно», принимаешь сам, но выносишь в пул-реквест отдельным пунктом.

Задачу откладываешь, а не ждёшь ответа, когда ей нужно что-то вне репозитория (аккаунт, токен, платный сервис, устройство) или три попытки починить одну и ту же проверку не помогли. В задачу пишешь комментарий, чего не хватает, и берёшь следующую. Ждёшь человека, только когда готовых задач не осталось.
