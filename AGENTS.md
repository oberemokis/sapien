# sapien

## Код

Устройство, слои и правила против связанности описаны в `docs/architecture.md`. Домен живёт крейтом в `crates/` и пакетом в `packages/`, а `apps/desktop` их только собирает. Новый домен сначала получает место в дереве документа, потом код.

Команды: `pnpm typecheck` (tsc и `cargo check`), `pnpm lint` (oxlint с границами слоёв, `cargo fmt --all --check`, `cargo clippy` с `-D warnings`, secretlint), `pnpm test` (vitest и `cargo test`). Cargo работает по workspace из корневого `Cargo.toml`, общий `target/` лежит в корне. Cargo запускают корневые задачи turbo `rust:*` со входами в `turbo.json`, и без правок в Rust они приходят из кеша. Все три гоняет CI, первые два ещё и хук перед коммитом. На пул-реквесте CI берёт задачи интерфейса только у изменённых пакетов (`--affected`) и хранит кеш turbo между прогонами. `pnpm audit:deps` (pnpm audit с уровня high и cargo audit) гоняет отдельный workflow `audit.yml` на пул-реквесте и раз в неделю, исключение записывается с причиной и условием снятия: для npm в `auditConfig` в `pnpm-workspace.yaml`, для Rust в `.cargo/audit.toml`. Окно приложения поднимает `pnpm dev`, интерфейс в браузере без Rust `pnpm dev:web`. Переменная окружения, которую задают снаружи, объявляется в `globalPassThroughEnv` в `turbo.json`: turbo отдаёт задачам только объявленные, и незаявленная молча не действует.

pnpm ставит только версии старше суток (`minimumReleaseAge`). Если установка дописала `minimumReleaseAgeExclude` в `pnpm-workspace.yaml`, выбранная версия моложе: поставь предыдущую явно и удали запись.

## Коммиты

Формат первой строки здесь Conventional Commits по-русски: `<тип>(<область>): <результат>`. Это перекрывает формат первой строки из скилла `commit`, всё остальное из него действует как есть: тело объясняет причину, автор только пользователь, хуки не обходятся.

- Тип: `feat` новая возможность, `fix` исправление, `refactor` перестройка без смены поведения, `perf` скорость, `test` только тесты, `docs` только документация, `chore` зависимости, CI, конфиги.
- Область: модуль, если правка живёт в одном, иначе сторона (`desktop` или `tauri`) или `ci`. Правка через весь репозиторий идёт без области: `docs: план функций`.
- Результат: одна фраза по-русски со строчной буквы, без точки, что стало, а не что сделано с файлами.
- Ломающее изменение формата команд Rust или сохранённых данных: `!` перед двоеточием и в теле строка `BREAKING CHANGE:` с тем, что сломается у потребителя.

Номер задачи в коммит не пишется: связь с задачей держит ветка и пул-реквест.

## Ветки

Каждое изменение, даже одна строка документации, идёт из задачи на GitHub через свою ветку в worktree `.worktrees/<ветка>` и приходит в `main` пул-реквестом: прямой push в `main` отклоняется. Корень репозитория делят несколько сессий, ветку в нём не переключают. Шаги от задачи до уборки после слияния в скилле `branches` в `.agents/skills/`.

## Задачи

План живёт в задачах, а не в репозитории: в документах он устаревает молча и расходится с задачами. Поэтому `docs/plan/` стоит в `.gitignore`.

## Автономная работа

Когда человек просит работать самостоятельно, задачи текущего этапа доводятся до слияния без вопросов к нему по скиллу `autonomous` в `.agents/skills/`.
