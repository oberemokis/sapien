# Архитектура

`apps/desktop` это десктопное приложение на Tauri v2 для работы с агентами вроде Claude Code и Codex в терминалах проектов: процесс на Rust держит окно и доступ к системе, интерфейс на React рисует веб-вью в этом окне. Данные пользователя живут на его устройстве, их читает и пишет Rust, своего сервера у приложения нет. Обе стороны разложены вертикальными модулями: модуль это область данных со своей дверью, снаружи виден только вход в него, внутри слои. Имена слоёв общие, поэтому знание переносится между сторонами.

Основное правило именования: каталог задаёт слой, имя файла задаёт операцию. Роль в имени файла (`projects.router.ts`) не нужна, её несёт папка.

Правила ниже действуют до появления кода, который им подчиняется. Где кода ещё нет, правило описывает, каким он должен быть.

## Слои и направление зависимостей

Интерфейс:

```
pages → components → flows → interactions → infrastructure
components → ui, model, store
```

Rust:

```
transport → use_case → domain
infrastructure → domain
```

Наружу не смотрит никто. `domain` и `model` не импортируют ничего своего. Сценарий не знает ни про Tauri, ни про хранилище: он работает с портом. `core` не знает ни одного модуля, сборка приложения живёт в `app/`.

Проверяется скриптом `scripts/check-boundaries.mjs`, он входит в `pnpm lint` и в хук перед коммитом. Компилятор эти правила не ловит: TypeScript одинаково пропускает импорт вниз и наверх. Что проверяется:

- сосед берётся только через `index.ts` модуля, `core` не знает ни модулей, ни `app`;
- `model` не импортирует значением react, TanStack и Tauri (типы можно); `ui/` модуля не знает остальных его слоёв; `interactions` не знают экрана; Tauri живёт только в `infrastructure` модулей и в `core`; `app`, `pages` и `components` не ходят в `infrastructure`.

На стороне Rust дверь держит сам язык: наружу модуля выходит только то, что объявлено `pub` в его `mod.rs`. Слой в Rust это файл (`domain.rs`), пока ему хватает одного, и каталог (`infrastructure/`), когда файлов несколько.

## Где живёт работа

Источник правды это устройство пользователя (local first). Приложение открывается, показывает и меняет данные без сети, а отсутствие сети не считается ошибкой.

Проект это папка на диске, в которой работает агент (модуль `projects`). Список проектов лежит файлом `projects.json` в папке данных приложения. Папку выбирает системный диалог в Rust, поэтому интерфейс не может подсунуть проектом чужой путь, а та же папка второй раз не добавляется. Убрать проект значит убрать его из списка вместе с сессиями, папку на диске приложение не трогает. Пропавшую папку окно показывает пометкой: сессии видны, а новый ответ и новая сессия отвечают `project_missing`. Сценарии агента получают путь проекта только через дверь `projects` (`projects::transport::folder`) и только если папка на месте.

Сессия это терминалы в папке проекта (модуль `agent`). Каждая лежит файлом `sessions/<id>.json` в папке данных приложения: проект, название и время. Название даёт агент заголовком терминала, пока его не дал человек (`named`): после этого заголовки агента его не меняют, а стёртое человеком имя снова отдаёт название агенту. У сессий из версий, где сессия была разговором с Claude Code, там же id этого разговора в поле `claude`: его продолжает `claude --resume <id>` в терминале сессии. Последний экран терминала каждой панели лежит рядом, в `sessions/screens/<id>/<панель>`, а разговор её агента в `<панель>.agent` там же, и удаляются они вместе с сессией. История чата из версий до формата 2 лежит нетронутой в `sessions/archive/`, окно её не показывает. Удаление сессии или проекта отказывает `agent_busy`, если хоть в одной панели удаляемой сессии работает агент. Терминалы остальных останавливаются перед удалением, и их экраны уже не сохраняются.

Сессия делится на панели (`agent/model/panes.ts`), у каждой своя оболочка. Раскладка это дерево делений надвое: деление слева направо или сверху вниз с долей первой части, и лежит она в хранилище окна по сессиям. Первая панель зовётся как сессия, остальные получают случайное имя. Правая кнопка в панели делит её в любую из четырёх сторон или закрывает, ⌘D делит активную панель вправо, ⇧⌘D вниз. Границу между панелями тянут мышью или двигают стрелками. Закрытая панель отдаёт место соседке и останавливает свою оболочку, последнюю панель закрывает только вкладка. Закрытая вкладка останавливает оболочки всех панелей, а раскладку помнит: открытая снова сессия запускает те же панели.

Окно показывает сессии вкладками (`agent/model/tabs.ts`). У каждого проекта свой набор вкладок, а видны вкладки открытого: сессия из левой панели открывается вкладкой своего проекта, «+» во вкладках начинает новую сессию в нём, а новый проект начинается с сессии сразу. Закрытая вкладка сессию не удаляет. Двойное нажатие или меню вкладки, как и строки в левой панели, переименовывают сессию командой `agent_session_rename`, имя одно на вкладку и строку в левой панели. Вкладки переставляют перетаскиванием, и так же переставляют сессии проекта в левой панели: до первой перестановки они идут свежими сверху, после неё держат порядок человека из хранилища окна, а новая сессия встаёт наверх. Закреплённая вкладка стоит левее остальных, с именем целиком и без крестика, закрыть её можно, только открепив. Порядок и закрепление лежат в хранилище окна вместе с вкладками. Сессию, в которой работает агент, отмечает точка во вкладках. В левой панели под сессией веткой дерева идут агенты, запущенные в её панелях, в порядке панелей, и точка стоит у того, кто работает. Шеврон у сессии сворачивает эту ветку, и тогда точку работы несёт сама сессия, а свёрнутые ветки лежат в хранилище окна. Строка агента открывает вкладку сессии и ставит фокус в его панель. Агент закрытой панели, который ещё доделывает работу, идёт последним, и его строка только открывает сессию.

Всё, что Rust пишет на диск, идёт через `durable.rs`: временный файл рядом, сброс на диск, переименование поверх и сброс папки. Оборванная запись или выключенное питание оставляют файл целым, в старой версии или в новой. Новый формат своего файла приложение пишет в новый файл тем же путём, а старый держит, пока перенос не закончился: оборванный перенос следующий запуск начинает заново со старого.

Синхронизации своей нет, учётной записи тоже: проекты и сессии живут на одном устройстве. Собственные файлы приложения не шифруются: их закрывает шифрование диска системы.

Блокировка приложения закрывает содержимое от чужого взгляда, пока человек отошёл, и включается в «Безопасности», по умолчанию она выключена. Окно закрывается после заданного времени без мыши и клавиатуры. Включённая блокировка закрывает приложение и с запуска. Заглушка на окне это модальный `<dialog>` поверх всех остальных, страница под ней остаётся смонтированной: агенты в терминалах работают, несохранённое не теряется, а сочетания клавиш до неё не доходят. Снимает заглушку проверка системы: на окне команда `app_unlock` (`unlock.rs`, крейт `robius-authentication`) спрашивает Touch ID или пароль учётной записи. Включить блокировку можно только после удачной проверки, поэтому без способа проверки она не включается вовсе. Если системе стало нечем спросить уже потом (сняли пароль учётной записи), заглушка снимается без проверки, иначе приложение закрылось бы насовсем: кто сидит в открытой сессии системы, и так читает файлы проектов с диска.

Формат собственных файлов приложения в папке данных имеет номер, файл `data-format` (`data_format.rs`). Новая версия при запуске, до окна, переносит файлы от записанного номера к своему по шагам и пишет номер после каждого шага, поэтому оборванный перенос следующий запуск продолжает с упавшего шага. Файла нет у новой установки и у версий до номера формата, это формат 1. Шаг держит прежний файл, пока новый не записан, как сказано выше, и не падает на пустой папке. Данные в хранилище окна (`localStorage`) переносит интерфейс сам, при чтении: каждый ключ и так читается с запасом на старое и испорченное.

Приложение обновляется из релизов GitHub (`updates.rs`, модуль `updates` окна). Версия живёт в одном месте, в `apps/desktop/package.json`: `tauri.conf.json` берёт её оттуда, у `Cargo.toml` версии нет. Тег `v<версия>` запускает `release.yml`: черновик релиза с заметками по пул-реквестам, одна сборка macOS на Apple Silicon и Intel с файлами обновления, подписанными своим ключом, и публикация, когда в `latest.json` есть обе архитектуры. Приложение только для macOS: релиз 0.2.0 был последним с Windows и Linux. Окно проверяет `latest.json` последнего релиза при запуске и раз в шесть часов, без сети не проверяет вовсе. Найденную версию с тем, что в ней изменилось, предлагает карточка в углу окна, а ставится обновление только по «Обновить и перезапустить». Плагин updater качает его, сверяет подпись с открытым ключом из `tauri.conf.json` и версию внутри подписи с объявленной (`requireSignedVersion`): иначе подменённый `latest.json` поставил бы старую подписанную версию. Окно плагин напрямую не зовёт, у него только команды `app_update_check` и `app_update_install`, и ставится ровно то, что показала последняя проверка. Закрытый ключ подписи живёт в секретах окружения `release` на GitHub и у владельца, в репозитории только открытый.

Агент это программа, которую человек запускает в терминале сессии: Claude Code, Codex, Pi, OpenCode, Cursor (`cursor-agent` или `agent`) или Gemini CLI, пока только на macOS. Сам sapien агента запускает, только чтобы продолжить его разговор после перезапуска. В настройках Rust проверяет Claude Code: ищет `claude` по абсолютным путям установки (`agent/infrastructure/claude_code.rs`), потому что приложение из Finder не видит PATH оболочки, и спрашивает версию (не ниже 2.1.299) и вход (`claude auth status`) с окружением без ключей API, иначе ключ перебил бы вход по подписке. Строки Claude Code в журнал не идут. Посередине окна сессия показывает свои панели, а вместо них плашку, если папки проекта нет.

Терминал (`agent/infrastructure/terminal.rs`, крейт `portable-pty`) это оболочка человека из `SHELL`, без неё zsh, оболочкой входа (`-l`) в псевдотерминале, в папке проекта. Окружение собрано заново: `HOME`, `USER`, `LOGNAME`, `TMPDIR`, `SSH_AUTH_SOCK`, `LANG` (без него `en_US.UTF-8`, иначе кириллица не набирается), системный `PATH` и `TERM=xterm-256color`. Остальное оболочка берёт из своих настроек, а окружение запуска приложения до неё не доходит. Панель запускает оболочку командой `terminal_open` с именем сессии и своим. При открытии окна оно сначала поднимает все панели открытых вкладок всех проектов командой `terminal_start`, без вкладки и размером 120 на 40, и показывает загрузку, пока они не запустились, но не дольше пяти секунд. Вкладка потом подключается к идущей оболочке, как после перезагрузки окна. Вывод уходит в окно байтами через канал Tauri, окно рисует его xterm.js (`agent/interactions/terminal.ts`), ввод и размер идут обратно командами по одному. Шрифт терминала, как у opencode 2.0, JetBrainsMono Nerd Font Mono: он лежит в приложении (`src/assets/fonts`), а значки Nerd Fonts в нём рисуют приглашения оболочки вроде starship и powerlevel10k без шрифта, поставленного в систему. Реестр терминалов в Rust (`agent/transport.rs`) держит по оболочке на панель и помнит последние 256 КБ её вывода. Терминал переживает переход на другую вкладку и перезагрузку окна: открытая снова вкладка получает помнящийся вывод и подключается к идущей оболочке, а полноэкранную программу Rust заставляет перерисоваться сменой размера. Когда оболочка кончилась или приложение выходит, вывод ложится файлом экрана панели, и следующая оболочка начинается под ним, после последовательности, которая выводит терминал из второго экрана (`ESC[?1047l`, не 1049: тот возвращает курсор на несохранённое место, и оболочка писала бы поверх экрана) и возвращает курсор, мышь, вести о фокусе и цвет. Помнящийся вывод всегда идёт первым сообщением канала, пусть и пустым, и окно не отвечает на запросы программ в нём: цвета, место курсора и вид терминала прежняя программа уже спросила вживую, а ответ сейчас попал бы в оболочку набранным текстом. Закрытая панель или вкладка останавливает оболочку сразу, а пока в ней работает агент, даёт ему закончить, но не дольше десяти минут без вывода. Останавливает Rust сигналом SIGHUP группе на переднем плане и группе оболочки, как закрытое окно терминала: интерактивная оболочка SIGTERM не слушает.

Какой агент запущен в каждой панели, Rust узнаёт по группе процессов на переднем плане: сторож раз в секунду спрашивает её у псевдотерминала (`tcgetpgrp`), а у новой группы читает командную строку (`ps -o args=`) и ищет имя агента в первых трёх словах, поэтому узнаётся и агент, поставленный через npm скриптом node. Первые три секунды новая группа перепроверяется: оболочка сначала порождает свою копию и только потом запускает в ней команду. Работает ли агент, Rust судит по выводу: агент на переднем плане и печатал в последние три секунды. Вывод в первые 300 мс после ввода и нового размера это эхо и перерисовка, работой он не считается. Имя сессии даёт заголовок терминала (OSC 0 и 2), который ставит агент: без значков работы в начале, а заголовок из одного имени агента ничего не называет. Сессия, в которой агент взялся за работу, поднимается в списке. О каждой перемене Rust шлёт окну `agent-sessions`, по которому оно перечитывает сессии.

После перезапуска агент панели продолжает свой разговор, как в herdr. Какой разговор идёт, sapien узнаёт от интеграции агента (`agent/infrastructure/integrations.rs`), которую человек подключает в настройках «Агент». Claude Code, Codex и Cursor получают хук на начало разговора в своих настройках (`~/.claude/settings.json`, `~/.codex/hooks.json`, `~/.cursor/hooks.json`, рядом с хуками человека), Pi и OpenCode свой файл в папке, которую читают сами (`~/.pi/agent/extensions/sapien.ts`, `~/.config/opencode/plugins/sapien.js`). Отключение снимает только своё. Хук зовёт само приложение подкомандой `sapien hook <агент>`, расширения пишут сами: весть `{ pane, agent, id, cwd, transcript, source }` идёт в Unix-сокет `hooks-<pid>.sock` в папке данных (права 0600, `agent/infrastructure/hooks.rs`). Сокет, панель и путь к приложению хук берёт из окружения оболочки панели (`SAPIEN_SOCKET`, `SAPIEN_PANE`, `SAPIEN_BIN`), поэтому вне sapien он молча ничего не делает. Хук субагента Claude Code, хук Claude Code, который зовёт Cursor, и вложенный Codex разговор панели не сообщают. Новый id того же агента меняет разговор, только когда агент сменил его сам (`/clear`, `/resume`): агент, которого агент панели запустил командой, начинает свой разговор, и тот панели не нужен. Разговор лежит рядом с экраном панели, `sessions/screens/<id>/<панель>.agent`, и стирается, когда из агента вышли и на переднем плане снова оболочка. Терминал, который остановило приложение (выход, закрытая вкладка), разговор помнит. Новая оболочка такой панели получает команду, как набранную, когда после первого вывода помолчала 300 мс, то есть дописала приглашение: `cd '<папка>' && claude --resume '<id>'`, `codex resume`, `pi --session`, `opencode --session` или `cursor-agent --resume`. Человек, который начал набирать раньше, команду не получает. Разговор, файла которого (`transcript`) нет, забывается без команды: агент запустили и закрыли, ничего не написав, и продолжать нечего. Codex запускает новый хук, только когда человек доверился ему в `/hooks`.

С машины файлы проектов уходят только через агентов, которых человек запустил в терминале, и по их правилам. Свои запросы Rust шлёт только на свой адрес (`egress.rs`): GitHub на адрес из кода, GitLab на тот, что ввёл человек. Обновление ходит своим клиентом плагина на GitHub по адресу из `tauri.conf.json`, без ключей и без данных человека. Перенаправлениям клиенты не следуют, потому что с ними токен ушёл бы на чужой адрес, а отказ пишется в журнал приложения одним источником адреса, без пути и параметров.

GitHub и GitLab подключаются по личному токену (модуль `forge`). Токен уходит в Rust и лежит в системном хранилище паролей, адрес сервера и логин лежат файлом `forge.json` в папке данных. Подключение сохраняется, только когда сервер ответил владельцем токена (`/user` у GitHub, `/api/v4/user` у GitLab), а ответ не от API даёт `forge_host_invalid`. GitLab бывает своим, его адрес только по https. Что агент делает с подключёнными сервисами и что попадает во «Входящие», пока не решено: экран «Входящие» это заглушка, и в левой панели ссылки на него пока нет.

Своего сервера у приложения нет: всё, что ему нужно, лежит на устройстве или приходит от GitHub и GitLab напрямую в Rust. Сервер появится, когда понадобится то, что без него не получить, например синхронизация. Rust держит то, что принадлежит машине: файлы, окна, системные API. Интерфейс показывает и не решает того, что может проверить Rust.

Настройки устройства (язык, тема, ширина панели, открытые вкладки, раскладка панелей, порядок сессий в левой панели и свёрнутые в ней ветки агентов) интерфейс хранит в `localStorage` окна: они принадлежат устройству и между устройствами не переезжают.

## Правила

### Модуль выставляет наружу один файл

`modules/<m>/index.ts` отдаёт именованные хуки и компоненты. `modules/<m>/mod.rs` отдаёт команды и то, что нужно корню для сборки. Внутренности модуля снаружи не импортирует никто.

Исключение одно: тест подменяет границу процесса и потому знает, какой файл её держит.

### Путь наружу модуля идёт через псевдоним

В desktop `@/` указывает на `src`. Внутри модуля импорт относительный (`./model/x`, `../model/x`), за его пределы только по псевдониму. Внутри `core` то же правило: соседний каталог берётся через псевдоним, файл рядом как `./icon`.

Так путь перестаёт зависеть от глубины файла: `../../../../core/ui/icon` читается как загадка и ломается при первом же переносе. Относительный путь внутри модуля оставлен намеренно, иначе переименование модуля правило бы каждый файл внутри него.

Псевдоним desktop объявляется всем, кто резолвит импорты сам: `tsconfig.json` для компилятора, `vitest.config.ts` для тестов, `vite.config.ts` для сборки. Пропущенный резолвер падает не на сборке, а на первом запуске.

Обойти границу через псевдоним нельзя: `scripts/check-boundaries.mjs` сводит `@/modules/projects/model/x` и `../../projects/model/x` к одному и тому же адресу.

### Ошибка это код, а не текст

Ошибка несёт вид и код, текста в ней нет. Команда Rust возвращает `Result<T, AppError>`, где `AppError` сериализуется в вид и код. Перевод делает интерфейс по коду.

Исключение одно: объяснение отказа от чужого сервера, например ответ GitLab на запрос, который он не принял. Команда кладёт его рядом с кодом в `detail` как есть. Перевести его нельзя, а без него причину отказа не найти, поэтому интерфейс показывает его после своего текста по коду.

### Порт объявляет потребитель

В Rust порт это trait в `ports.rs` модуля: он описывает, что нужно сценариям, а `infrastructure` это выполняет. Реализация объявляет trait явно, поэтому он заводится только на границе с внешним миром.

### Сценарий не решает за транспорт

Сценарий делает одно дело: «прочитать запись» и «завести её при первом обращении» это один сценарий, а не два. Команда Rust только разбирает вход, зовёт сценарий и ничего не решает сама.

### Интерфейс знает про Rust в одном слое

`infrastructure/<модуль>.api.ts` это единственное место модуля, где живут `invoke`, события и плагины Tauri. Выше по слоям ходят за данными модуля, а не за командой.

`interactions/` держит кеш: ключ, `staleTime`, `enabled`, инвалидация. Центрального реестра ключей нет, ключ выводится из имени команды. Мутация идёт через `useMutation` из TanStack Query и после успеха инвалидирует кеш по префиксу ключа.

Данные из Rust живут только в кеше Query и в стор не копируются: копия расходится с кешем при первой же инвалидации. `store/` держит то, чего в Rust нет и что нужно нескольким компонентам (вкладки, раскладка панелей). Состояние одного компонента остаётся в `useState`.

`flows/` появляется там, где экран собирает больше одного источника. Где источник один, потока нет: пустая обёртка вокруг запроса ничего не объясняет.

Окно без процесса Rust (`pnpm dev:web`, тесты) команд не получит: `invoke` там падает. Тест подменяет границу через `mockIPC` из `@tauri-apps/api/mocks`, но не свой `infrastructure`.

### Права окна объявляются явно

Плагин Tauri получает права в `src-tauri/capabilities/default.json`, иначе его вызов падает отказом во время работы, а не на сборке. Право выдаётся на окно и на конкретное действие плагина, а не набором `*:default`, если набор открывает больше, чем нужно экрану.

CSP задан в `tauri.conf.json` и в разработке выключен (`devCsp: null`), потому что Vite вставляет стили и держит сокет горячей замены. Новый источник (адрес, шрифт или картинка из сети) расширяет CSP точечно по директиве.

### Окно показывает только свой интерфейс

Ответ агента собран из чужого текста: файлов проекта, вывода команд, страниц из сети. Он поэтому считается чужим, а у окна есть доступ к системе через команды Rust. Отсюда правила.

- Окно строит `links.rs`, а не конфиг (`"create": false`): только так на него вешаются проверки переходов. Переход на чужой адрес отменяется, новые окна запрещены, адрес `http`, `https` или `mailto` уходит в браузер системы. Другие схемы не открываются нигде.
- Окно показывает ответ агента текстом, HTML из него не выводится. `dangerouslySetInnerHTML` запрещён правилом oxlint `react/no-danger`. Разметка ответа, когда появится, сначала его очистит.
- Ссылка открывается через команду `open_link`: адрес проверяет Rust, окно его только передаёт.
- Права окна в `capabilities/default.json` перечислены поштучно, без `core:default`. Новой возможности окна нужно своё право с причиной в описании.
- CSP закрывает `object-src`, `frame-src`, `form-action` и держит `base-uri` на своём origin. Разрешение на скрипт со стороны в него не добавляется.

### Секрет живёт в системном хранилище и в Rust

Токены GitHub и GitLab лежат в Связке ключей macOS. На окне с ним работает `secrets.rs` через крейт `keyring`.

- Окно отдаёт токен в Rust один раз, командой `forge_connect`, и сразу забывает: поле пустеет сразу после отправки. Обратно приходят только адрес сервера и логин. Команды, которая вернула бы токен, нет и не будет.
- Запрос с токеном делает Rust и подставляет его сам через `Secrets::get`, заголовок помечен как чувствительный. Токен не попадает в файлы настроек, историю сессий, журнал, логи, тексты ошибок и экспорт. Агенту он не передаётся.
- Имя секрета это вариант `SecretName`: окно не может записать в системное хранилище ничего, кроме известных записей. Новый секрет добавляет свой вариант.
- Если Связка ключей не приняла токен, он живёт только в памяти Rust до закрытия приложения, после перезапуска подключение показывается отключённым. Своего шифрования и открытого текста на диске нет.

### Состояние «в пути» отличается от «нет»

Пока данные `undefined`, экран показывает заглушку того же размера, а не пустой список. Ожидание не меняет размеры элемента: подпись кнопки остаётся, меняется значок той же величины.

### Соседние модули связывает страница

Модуль не импортирует соседа значением, даже через дверь, если связь нужна только на одном экране: её собирает страница. Карточка одного модуля даёт слот, страница ставит в него компонент другого.

### Ключ перевода проверяет компилятор

`core/i18n` запускает i18next и объявляет основной словарь в `CustomTypeOptions`. После этого `t` из `useTranslation()` принимает только существующие ключи в любом файле, и опечатку ловит компилятор. Словарь без этого объявления превращает `t` в функцию от любой строки.

Основной словарь `ru.ts`, английский `en.ts` объявлен его формой: пропущенный или лишний ключ в переводе тоже ловит компилятор. Без выбора окно на английском, выбор хранит модуль `appearance` и до первой отрисовки отдаёт его i18next, атрибуту `lang` страницы и Rust для меню macOS. Тесты идут на русском: элементы в них ищутся по русским подписям.

### Переход идёт по пути из дерева

`Link` и `navigate` берут `to` и `params` из дерева маршрутов (`src/route-tree.gen.ts`), и оба проверяет компилятор: переименованная страница ломает сборку, а не ссылку. Путь, собранный строкой (`` `/projects/${id}` ``), компилятор не проверит, поэтому параметр передаётся через `params`. Параметры запроса страница описывает в `validateSearch` схемой zod и читает через `useSearch`, а не из `window.location`.

Дерево пишет плагин роутера при `vite dev` и `vite build`, и оно лежит в репозитории: `tsc` в CI запускается без Vite.

### Готовое вместо самописного

Загрузка и кеш берутся из TanStack Query, адрес из TanStack Router. Подписка на событие браузера идёт через `useSyncExternalStore` или эффект с отпиской в cleanup: своя версия без отписки рано или поздно течёт. То же для Rust: системное API берётся плагином Tauri, если плагин есть.

### Пакет появляется при втором потребителе

Пакет это граница, а не папка. Пакет в `packages/` появляется, когда один и тот же код нужен двум потребителям значением.

### Тест лежит рядом с проверяемым

Тест это `*.spec.ts` (`*.spec.tsx`, если в нём разметка) рядом с файлом. На интерфейсе основная масса входит через компонент модуля: настоящие слои, подмена только на границе процесса через `mockIPC`. Модуль в тесте собирается через дверь, а не из внутренностей: тогда перекладка файлов внутри модуля тесты не ломает. Изолированные тесты только у домена и у чистой модели интерфейса. Тест Rust живёт в `#[cfg(test)] mod tests` того же файла; сценарий проверяется на двойниках портов, команда через `tauri::test`.

## Как добавить

Команду Rust: сценарий в `use_case`, функция с `#[tauri::command]` в `transport`, строка в `generate_handler!` в `lib.rs` полным путём `модуль::transport::команда`. Макрос ищет рядом с командой скрытые функции, которые переэкспорт через `pub use` не уносит, поэтому `transport` открыт из `mod.rs` целиком. На интерфейсе метод в `infrastructure/<модуль>.api.ts`, файл в `interactions/` и строка в двери модуля.

Модуль: каталог по шаблону выше на нужной стороне, `mod` в `lib.rs`, каталог в `src/modules/` интерфейса, страница в `pages/` окна.

Если шагов выходит больше, значит общее не доехало до `core/`.

## Отвергнутые варианты

Слои сверху, модули внутри (`layers/use-case/<сущность>`). Барель на каждом слое открывает любой сценарий любому файлу, а сущность размазывается по четырём каталогам. При модулях сверху дверь одна и её стережёт проверка границ.

Клиентский `use-case` на каждую команду. Половина сценариев была бы строкой «вызови Rust». Слой заведём, когда у сценария на интерфейсе появится что решать; пока эту роль несёт `interactions`.

Сервер-заготовка на будущее. До ноября 2026 рядом с окном жил `apps/api` на Hono с одним маршрутом `/health`, и его клиент не звал никто. Ради него окно держало hono, адрес в CSP и отдельный процесс в `pnpm dev`. Понадобится сервер, он вернётся из истории git.

Vue вместо React. React выбран в расчёте на приложение для телефона: Expo работает только на React Native, а у Vue аналога нет (Vue Native заброшен, NativeScript-Vue сильно меньше, остальные варианты это webview). Телефон отложен, но если он вернётся, его интерфейс напишется на том же языке, что и окно.

TanStack Start вместо голого React. Tauri раздаёт окну статические файлы, серверного рендеринга там нет.
