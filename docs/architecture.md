# Архитектура

`apps/desktop` это десктопное приложение на Tauri v2 для менеджеров и аналитиков: подключения к трекерам задач и хранилищам кода, аналитика и расписывание задач по ней. Пока в нём каркас окна и подключения GitHub и GitLab, остальное придёт задачами. процесс на Rust держит окно и доступ к системе, интерфейс на React рисует веб-вью в этом окне. Данные пользователя живут на его устройстве, их читает и пишет Rust, своего сервера у приложения нет.

Код разложен по доменам. Домен это область данных со своей дверью: у него свой крейт Rust в `crates/` и свой пакет TypeScript в `domains/`, снаружи виден только вход, внутри слои. Домены друг с другом никак не связаны, общее без домена лежит в `packages/` и `crates/kernel`. Приложение в `apps/desktop` доменов не содержит, оно их собирает: корень композиции и команды на стороне Rust, страницы и сборка окна на стороне интерфейса. Имена доменов и слоёв общие для двух языков, поэтому знание переносится между сторонами.

Основное правило именования: каталог задаёт слой, имя файла задаёт операцию. Роль в имени файла (`projects.router.ts`) не нужна, её несёт папка.

Правила ниже действуют до появления кода, который им подчиняется. Где кода ещё нет, правило описывает, каким он должен быть.

## Домены

| Домен | Что держит | Крейт | Пакет | Команды Rust |
| --- | --- | --- | --- | --- |
| подключения | GitHub и GitLab по токену, связка ключей, политика запросов | `sapien-forge` | `@sapien/forge` | `forge_*` |
| блокировка | заглушка, таймер простоя, Touch ID | `unlock.rs` приложения | `@sapien/security` | `security_*` |
| обновления | проверка и установка | `updates.rs` приложения | `@sapien/updates` | `updates_*` |
| вид | тема, масштаб, язык | `language.rs` приложения | `@sapien/appearance` | `appearance_*` |
| раскладка окна | ширина левой панели, края | нет | `@sapien/layout` | нет |

Блокировка, обновления и язык остаются файлами крейта приложения: каждый из них это одна-две команды поверх плагина Tauri или системного API, и без Tauri от них ничего не остаётся.

Общий код без домена: крейт `sapien-kernel` (`AppError`, запись файла целиком, механизм переноса формата данных) и пакеты в `packages/`: `@sapien/ipc` (команды, события и типы, сгенерированные из Rust, и подделка Rust для `dev:web` и тестов), `@sapien/ui` (вид без домена и токены темы), `@sapien/i18n`, `@sapien/device` (настройки устройства в `localStorage`, подписки на окно) и `@sapien/testing` (настройка тестов).

## Направление зависимостей

Между крейтами, стрелка значит «зависит от»:

```
sapien (приложение) ──► forge ──► kernel
```

Между пакетами:

```
apps/desktop (app, pages) ──► domains/*, packages/*
domains/<домен>           ──► packages/*: ipc, ui, i18n, device
packages/*                ──► packages/*
```

## Границы между доменами

Домены никак не связаны друг с другом: ни импортом, ни типом, ни командой Rust, ни строкой словаря, ни ключом хранилища. Встречаются они только в окне: страница ставит компоненты двух доменов рядом и связывает их слотом. Общее для двух доменов уходит вниз, в `packages/` или `sapien-kernel`, а не к соседу.

| Граница | Чем держится |
| --- | --- |
| домен не импортирует соседа, даже тип | соседа нет в `package.json` домена, и pnpm не кладёт его в `node_modules`: путь не находят ни компилятор, ни сборка |
| в `package.json` домена нет другого домена, в `package.json` общего пакета нет ни одного | `scripts/check-boundaries.mjs` |
| домен не видит чужих строк | у пакета свой `tsc` и свой `test-setup.ts`: чужое пространство имён в них не объявлено и не загружено |
| домен зовёт только свои команды и события Rust | префикс домена в имени команды и `scripts/check-boundaries.mjs` |
| доменный крейт не знает других доменных | соседа нет в `Cargo.toml`, это проверяет `scripts/check-boundaries.mjs` |
| доменный крейт в крейте приложения называют только `lib.rs` и `commands/<домен>.rs`, а файл команд берёт только свой крейт | `scripts/check-boundaries.mjs`: крейт приложения зависит от всех доменных, и Cargo этого не ловит |
| файлы доменов в крейте приложения (`unlock.rs`, `updates.rs`) не знают друг друга | ревью |
| ключи `localStorage` и Query не пересекаются | префикс домена, ревью |

Ключ `localStorage` начинается с `sapien.<домен>`, ключ Query с имени домена: `["forge", "status"]`. Ключи `sapien.theme`, `sapien.scale`, `sapien.language` и `sapien.lock` записаны до этого правила и остаются как есть: смена ключа теряет выбор, сделанный под прежним. Ключи, атрибуты DOM, сочетания клавиш и типы чужого домена из `@sapien/ipc` (`UnlockCode` в forge) инструменты не видят, это ловит ревью.

Язык окна в `language.rs` общий, а не домена вида: его читают меню macOS и системное окно разблокировки. Вид только задаёт его командой `appearance_set_language`.

## Слои внутри домена

Интерфейс:

```
pages → components → flows → interactions → infrastructure
components → ui, model, store
```

Rust:

```
commands приложения → use_case → domain
infrastructure → domain
```

Наружу не смотрит никто. `domain` и `model` не импортируют ничего своего. Сценарий не знает ни про Tauri, ни про хранилище: он работает с портом. Крейт домена не зависит от Tauri вовсе: команды, события и каналы окна живут в крейте приложения. Общие пакеты (`@sapien/ui`, `@sapien/ipc`, `@sapien/device`, `@sapien/i18n`) не знают ни одного домена, сборка приложения живёт в `app/`. `@sapien/ipc` несёт команды и типы всех доменов, потому что Rust пишет их одним файлом, но ни одного доменного пакета он не импортирует.

Слой в Rust это файл (`domain.rs`), пока ему хватает одного, и каталог (`infrastructure/`), когда файлов несколько.

## Как держатся границы

Компилятор TypeScript правила слоёв не ловит: он одинаково пропускает импорт вниз и наверх. Поэтому границы держат инструменты, каждый своё:

- соседа можно взять только через дверь: `exports` пакета открывает одну точку `.`, крейт отдаёт наружу только `pub` из `lib.rs`;
- зависимость, которой нет в `package.json` или `Cargo.toml`, не находится при сборке, а круг между пакетами или крейтами роняет turbo и Cargo;
- границы между доменами, которых не ловят сборка и Cargo, проверяет `scripts/check-boundaries.mjs` в `pnpm lint`: зависимости в `package.json` и `Cargo.toml`, команды и события Rust в `domains/<домен>/`, крейты в `commands/<домен>.rs`;
- слои внутри пакета домена держит oxlint: `no-restricted-imports` в `overrides` по каталогам `domains/*/src/<слой>/` и `import/no-cycle`. `model` не импортирует значением react, TanStack, Tauri и `@sapien/ipc` (типы можно), `ui/` не знает остальных слоёв, `interactions` не знают экрана, `components` не ходят в `infrastructure`, Tauri значением только в `infrastructure`, команды Rust только в `interactions` и `infrastructure`, `@sapien/ipc/fake` только в тестах;
- `cargo clippy --workspace --all-targets -- -D warnings` входит в `pnpm lint`.

Окно `apps/desktop/src` держат те же `overrides`: страницы не зовут команды Rust и Tauri значением, а подделку `@sapien/ipc/fake` ставит только `app/rust.ts`. Внутренности пакета окну не видны: `exports` открывает только `.`, и `@sapien/forge/src/model/forge` не находит ни компилятор, ни сборка.

## Где живёт работа

Источник правды это устройство пользователя (local first). Приложение открывается, показывает и меняет данные без сети, а отсутствие сети не считается ошибкой.

Всё, что Rust пишет на диск, идёт через `sapien_kernel::durable`: временный файл рядом, сброс на диск, переименование поверх и сброс папки. Оборванная запись или выключенное питание оставляют файл целым, в старой версии или в новой. Новый формат своего файла приложение пишет в новый файл тем же путём, а старый держит, пока перенос не закончился: оборванный перенос следующий запуск начинает заново со старого.

Синхронизации своей нет, учётной записи тоже: данные живут на одном устройстве. Собственные файлы приложения не шифруются: их закрывает шифрование диска системы.

Блокировка приложения закрывает содержимое от чужого взгляда, пока человек отошёл, и включается в «Безопасности», по умолчанию она выключена. Окно закрывается после заданного времени без мыши и клавиатуры. Включённая блокировка закрывает приложение и с запуска. Заглушка на окне это модальный `<dialog>` поверх всех остальных, страница под ней остаётся смонтированной: несохранённое не теряется, а сочетания клавиш до неё не доходят. Снимает заглушку проверка системы: на окне команда `security_unlock` (`unlock.rs`, крейт `robius-authentication`) спрашивает Touch ID или пароль учётной записи. Включить блокировку можно только после удачной проверки, поэтому без способа проверки она не включается вовсе. Если системе стало нечем спросить уже потом (сняли пароль учётной записи), заглушка снимается без проверки, иначе приложение закрылось бы насовсем: кто сидит в открытой сессии системы, и так читает файлы с диска.

Формат собственных файлов приложения в папке данных имеет номер, файл `data-format`: шаги перечисляет `data_format.rs` приложения, проходит их `sapien_kernel::migrate`. Новая версия при запуске, до окна, переносит файлы от записанного номера к своему по шагам и пишет номер после каждого шага, поэтому оборванный перенос следующий запуск продолжает с упавшего шага. Файла нет у новой установки и у версий до номера формата, это формат 1. Шаг держит прежний файл, пока новый не записан, как сказано выше, и не падает на пустой папке. Данные в хранилище окна (`localStorage`) переносит интерфейс сам, при чтении: каждый ключ и так читается с запасом на старое и испорченное.

Приложение обновляется из релизов GitHub (`updates.rs`, пакет `@sapien/updates`). Версия живёт в одном месте, в `apps/desktop/package.json`: `tauri.conf.json` берёт её оттуда, у `Cargo.toml` версии нет. Тег `v<версия>` запускает `release.yml`: черновик релиза с заметками по пул-реквестам, одна сборка macOS на Apple Silicon и Intel с файлами обновления, подписанными своим ключом, и публикация, когда в `latest.json` есть обе архитектуры. Приложение только для macOS: релиз 0.2.0 был последним с Windows и Linux. Окно проверяет `latest.json` последнего релиза при запуске и раз в шесть часов, без сети не проверяет вовсе. Найденную версию с тем, что в ней изменилось, предлагает карточка в углу окна, а ставится обновление только по «Обновить и перезапустить». Плагин updater качает его, сверяет подпись с открытым ключом из `tauri.conf.json` и версию внутри подписи с объявленной (`requireSignedVersion`): иначе подменённый `latest.json` поставил бы старую подписанную версию. Окно плагин напрямую не зовёт, у него только команды `updates_check` и `updates_install`, и ставится ровно то, что показала последняя проверка. Закрытый ключ подписи живёт в секретах окружения `release` на GitHub и у владельца, в репозитории только открытый.

Свои запросы Rust шлёт только на свой адрес (`egress.rs`): GitHub на адрес из кода, GitLab на тот, что ввёл человек. Обновление ходит своим клиентом плагина на GitHub по адресу из `tauri.conf.json`, без ключей и без данных человека. Перенаправлениям клиенты не следуют, потому что с ними токен ушёл бы на чужой адрес, а отказ пишется в журнал приложения одним источником адреса, без пути и параметров.

Что отдают GitHub, GitLab и YouTrack, на каком тарифе и в каких пределах запросов, описано в [integrations.md](./integrations.md).

GitHub и GitLab подключаются по личному токену (крейт `sapien-forge`). Токен уходит в Rust и лежит в системном хранилище паролей, адрес сервера и логин лежат файлом `forge.json` в папке данных. Подключение сохраняется, только когда сервер ответил владельцем токена (`/user` у GitHub, `/api/v4/user` у GitLab), а ответ не от API даёт `forge_host_invalid`. GitLab бывает своим, его адрес только по https. Что агент делает с подключёнными сервисами и что попадает во «Входящие», пока не решено: экран «Входящие» это заглушка, и в левой панели ссылки на него пока нет.

Своего сервера у приложения нет: всё, что ему нужно, лежит на устройстве или приходит от GitHub и GitLab напрямую в Rust. Сервер появится, когда понадобится то, что без него не получить, например синхронизация. Rust держит то, что принадлежит машине: файлы, окна, системные API. Интерфейс показывает и не решает того, что может проверить Rust.

Настройки устройства (язык, тема, ширина панели) интерфейс хранит в `localStorage` окна: они принадлежат устройству и между устройствами не переезжают. Каждую объявляет `defineSetting` из `@sapien/device` с ключом, разбором и значением по умолчанию: побитая запись или закрытое политикой хранилище дают значение по умолчанию, а не падение окна.

## Правила

### Домен выставляет наружу один файл

`domains/<домен>/src/index.ts` отдаёт именованные хуки и компоненты. `crates/<домен>/src/lib.rs` отдаёт сервис, порты и типы, которые нужны корню композиции и командам домена. Команды Tauri живут не в крейте домена, а в `src-tauri/src/commands/<домен>.rs` приложения. Внутренности домена снаружи не импортирует никто.

Исключение одно: тест подменяет границу процесса и потому знает, какой файл её держит.

### Путь наружу домена идёт через имя или псевдоним

Пакет берётся по имени (`@sapien/forge`), крейт тоже (`sapien_forge`). Внутри `apps/desktop` псевдоним `@/` указывает на `src`: страница берёт `@/settings`, а не `../settings`. Внутри пакета импорт относительный (`./model/x`, `../model/x`).

Так путь окна перестаёт зависеть от глубины файла: `../../../app/rust` читается как загадка и ломается при первом же переносе. Относительный путь внутри пакета оставлен намеренно, иначе переименование пакета правило бы каждый файл внутри него.

Псевдоним desktop объявляется всем, кто резолвит импорты сам: `tsconfig.json` для компилятора, `vitest.config.ts` для тестов, `vite.config.ts` для сборки. Пропущенный резолвер падает не на сборке, а на первом запуске.

Обойти дверь пакета нельзя: путь в его `src` не находит ни компилятор, ни сборка, потому что `exports` открывает только `.`.

### Ошибка это код, а не текст

Ошибка несёт вид и код, текста в ней нет. Команда Rust возвращает `Result<T, AppError>`, где `AppError` сериализуется в вид и код. Перевод делает интерфейс по коду.

Код это вариант перечисления домена, строкой его не написать: `AppError::invalid(ForgeCode::TokenEmpty)`. Перечисление объявляет макрос `error_codes!` из `sapien-kernel`, строка для окна записана рядом с вариантом один раз. Перечисление лежит в `domain.rs` крейта (у файлов приложения в самом файле) и попадает в `@sapien/ipc` объединением строк. Окно держит подсказки таблицей `{ код: подсказка } satisfies Record<ForgeCode, string>`: код, который добавит Rust, не скомпилируется, пока окно не решит, что о нём сказать, своей подсказкой или общей причиной. Перевод каждой подсказки проверяет `t`.

Исключение одно: объяснение отказа от чужого сервера, например ответ GitLab на запрос, который он не принял. Команда кладёт его рядом с кодом в `detail` как есть. Перевести его нельзя, а без него причину отказа не найти, поэтому интерфейс показывает его после своего текста по коду.

### Порт объявляет потребитель

В Rust порт это trait в `ports.rs` крейта: он описывает, что нужно сценариям, а `infrastructure` это выполняет. Реализация объявляет trait явно, поэтому он заводится только на границе с внешним миром.

### Сценарий не решает за транспорт

Сценарий делает одно дело: «прочитать запись» и «завести её при первом обращении» это один сценарий, а не два. Команда Rust только разбирает вход, зовёт сценарий и ничего не решает сама.

### Домены собирает корень композиции

`lib.rs` крейта приложения один раз собирает пути (папка данных, домашняя папка) и адаптеры доменов и отдаёт их Tauri через `.manage()`. Команда получает готовый сервис из `State`. Искать папку данных и собирать адаптер на каждом вызове команды нельзя: так команда превращается в локатор служб, а подменить адаптер в тесте становится нечем. На интерфейсе то же делает `app/`: словари пакетов, клиент Query, роутер, подделка Rust в `dev:web`.

DI-контейнера нет ни на одной стороне: сборка занимает экран кода и видна целиком.

### Интерфейс знает про Rust в одном слое

Команды, события и типы окна генерирует из Rust tauri-specta в `packages/ipc/src/bindings.gen.ts`. Файл лежит в репозитории, как дерево маршрутов: тест в `src-tauri/src/lib.rs` пишет его заново, и если в коммите он другой, переписывает его и падает. Поэтому поле, переименованное в Rust, сначала роняет `pnpm test`, а с переписанным файлом и `pnpm typecheck`. Отказ команды бросается значением `AppError`, как у `invoke`, иначе TanStack Query принял бы его за ответ.

Значения из `@sapien/ipc` берут `interactions`, а ещё `infrastructure`, где команда нужна без кеша (язык меню, ссылка в браузер), и `settings/menu.ts` окна, который слушает пункт «Настройки…» меню. Обёртки над сгенерированной командой нет: обёртка в одну строку ничего не объясняет. Домен зовёт только свои команды, как сказано в правиле ниже. Тип из пакета годится любому слою. В `infrastructure` модуля остаётся то, что трогает DOM и хранилище окна: тема на `<html>`, `matchMedia`, ширина окна.

У типа, который Rust и читает, и пишет, генератор даёт две формы, `_Serialize` и `_Deserialize`. Дверь пакета отдаёт под обычным именем форму ответа Rust. Исключение `Progress`: его шлёт канал, а канал генератор описывает формой аргумента команды. Имя агента приходит строкой: список агентов знает Rust, а окно держит только их названия и чужое имя показывает как есть.

`interactions/` держит кеш: ключ, `staleTime`, `enabled`, инвалидация. Центрального реестра ключей нет, ключ выводится из имени команды. Мутация идёт через `useMutation` из TanStack Query и после успеха инвалидирует кеш по префиксу ключа.

Данные из Rust живут только в кеше Query и в стор не копируются: копия расходится с кешем при первой же инвалидации. `store/` держит то, чего в Rust нет и что нужно нескольким компонентам (раскладка окна). Состояние одного компонента остаётся в `useState`.

`flows/` появляется там, где экран собирает больше одного источника. Где источник один, потока нет: пустая обёртка вокруг запроса ничего не объясняет.

Окно без процесса Rust (`pnpm dev:web`, тесты) отвечает подделкой из `@sapien/ipc/fake`. У неё обработчик на каждую команду из `commands`, поэтому новая команда без подделки не компилируется. Ответ приходит через `setTimeout`: ответ микрозадачей прятал бы гонки с перерисовкой. Тест ставит `fakeRust` с нужным состоянием, а отказы и особые ответы задаёт `refuse` и `handle`, своего `mockIPC` у него нет. `pnpm dev:web` ставит `browserRust` из `app/rust.ts`, режимы выбирает хеш адреса (список в `fake/browser.ts`). Условие с `import.meta.env.DEV` сборка вырезает вместе с импортом, и в приложение подделка не попадает.

### Команда носит имя своего домена

Имя команды и события Rust начинается с имени домена, который их зовёт: `forge_connect`, `security_unlock`, `updates_check`, `appearance_set_language`. По имени виден владелец, и `scripts/check-boundaries.mjs` сверяет каждый `commands.<имя>` и `events.<имя>` в `domains/<домен>/` с именем папки. `@sapien/ipc` отдаёт все команды всем, и без префикса forge мог бы позвать разблокировку окна, а заметить это было бы нечем.

Команда без домена попадает в список общих в том же скрипте и только с причиной. Сейчас там одна `open_link`: ссылку в браузер системы открывает Rust для любого экрана. События окна без домена (`menu-settings`) слушает само окно, домену они не нужны.

Файл команд тоже принадлежит домену: `commands/<домен>.rs` берёт только `sapien_<домен>` и `sapien_kernel`, а из крейта приложения только `crate::events`. Чужой сервис из `State` ему не взять: тип сервиса лежит в чужом крейте. Кроме файлов команд, доменный крейт называет только корень композиции `lib.rs`.

### Права окна объявляются явно

Плагин Tauri получает права в `src-tauri/capabilities/default.json`, иначе его вызов падает отказом во время работы, а не на сборке. Право выдаётся на окно и на конкретное действие плагина, а не набором `*:default`, если набор открывает больше, чем нужно экрану.

CSP задан в `tauri.conf.json` и в разработке выключен (`devCsp: null`), потому что Vite вставляет стили и держит сокет горячей замены. Новый источник (адрес, шрифт или картинка из сети) расширяет CSP точечно по директиве.

### Окно показывает только свой интерфейс

Задачи, merge request и комментарии из подключённых сервисов это чужой текст, как и страницы из сети. Он поэтому считается чужим, а у окна есть доступ к системе через команды Rust. Отсюда правила.

- Окно строит `links.rs`, а не конфиг (`"create": false`): только так на него вешаются проверки переходов. Переход на чужой адрес отменяется, новые окна запрещены, адрес `http`, `https` или `mailto` уходит в браузер системы. Другие схемы не открываются нигде.
- Окно показывает чужой текст текстом, HTML из него не выводится. `dangerouslySetInnerHTML` запрещён правилом oxlint `react/no-danger`. Разметка, когда появится, сначала его очистит.
- Ссылка открывается через команду `open_link`: адрес проверяет Rust, окно его только передаёт.
- Права окна в `capabilities/default.json` перечислены поштучно, без `core:default`. Новой возможности окна нужно своё право с причиной в описании.
- CSP закрывает `object-src`, `frame-src`, `form-action` и держит `base-uri` на своём origin. Разрешение на скрипт со стороны в него не добавляется.

### Секрет живёт в системном хранилище и в Rust

Токены GitHub и GitLab лежат в Связке ключей macOS. На окне с ним работает `secrets.rs` крейта `sapien-forge` через крейт `keyring`.

- Окно отдаёт токен в Rust один раз, командой `forge_connect`, и сразу забывает: поле пустеет сразу после отправки. Обратно приходят только адрес сервера и логин. Команды, которая вернула бы токен, нет и не будет.
- Запрос с токеном делает Rust и подставляет его сам через `Secrets::get`, заголовок помечен как чувствительный. Токен не попадает в файлы настроек, журнал, логи, тексты ошибок и экспорт.
- Имя секрета это вариант `SecretName`: окно не может записать в системное хранилище ничего, кроме известных записей. Новый секрет добавляет свой вариант.
- Если Связка ключей не приняла токен, он живёт только в памяти Rust до закрытия приложения, после перезапуска подключение показывается отключённым. Своего шифрования и открытого текста на диске нет.

### Состояние «в пути» отличается от «нет»

Пока данные `undefined`, экран показывает заглушку того же размера, а не пустой список. Ожидание не меняет размеры элемента: подпись кнопки остаётся, меняется значок той же величины.

### Соседние пакеты связывает страница

Пакет не импортирует соседа значением, даже через дверь, если связь нужна только на одном экране: её собирает страница. Карточка одного пакета даёт слот, страница ставит в него компонент другого.

### Ключ перевода проверяет компилятор

`@sapien/i18n` отдаёт i18next интерфейс `Resources`, а пакет со строками дополняет его своим русским словарём под своим пространством имён в `src/dictionary.ts`. Компонент пакета берёт `t` из `useTranslation("<пакет>")`, и `t` принимает только ключи этого словаря: опечатку ловит компилятор пакета. Словарь без этого объявления превращает `t` в функцию от любой строки. Строку чужого пакета адресуют `пакет:ключ` (`forge:title` в навигации настроек), и `useTranslation` получает список пространств. Строки самого окна (входящие и рамка настроек) лежат пространством `translation` в `app/i18n`.

Словари собирает приложение и отдаёт `startI18n` все сразу: пространство, объявленное в `Resources` и забытое при запуске, не компилируется. Английский словарь объявлен формой русского (`Dictionary` из `@sapien/i18n`): пропущенный или лишний ключ в переводе тоже ловит компилятор. Без выбора окно на английском, выбор хранит пакет `appearance` и до первой отрисовки отдаёт его i18next, атрибуту `lang` страницы и Rust для меню macOS. Тесты идут на русском: элементы в них ищутся по русским подписям. Пакет запускает i18next в своём `test-setup.ts` только со своим словарём.

### Переход идёт по пути из дерева

`Link` и `navigate` берут `to` и `params` из дерева маршрутов (`src/route-tree.gen.ts`), и оба проверяет компилятор: переименованная страница ломает сборку, а не ссылку. Путь, собранный строкой (`` `/projects/${id}` ``), компилятор не проверит, поэтому параметр передаётся через `params`. Параметры запроса страница описывает в `validateSearch` схемой zod и читает через `useSearch`, а не из `window.location`.

Дерево пишет плагин роутера при `vite dev` и `vite build`, и оно лежит в репозитории: `tsc` в CI запускается без Vite.

### Готовое вместо самописного

Загрузка и кеш берутся из TanStack Query, адрес из TanStack Router. Подписка на событие браузера идёт через `useSyncExternalStore` или эффект с отпиской в cleanup: своя версия без отписки рано или поздно течёт. То же для Rust: системное API берётся плагином Tauri, если плагин есть.

### Домен получает крейт и пакет сразу, общий код при втором потребителе

Пакет и крейт это граница, а не папка. Домен получает их сразу: граница между доменами нужна с первого дня, иначе её прорастает связями быстрее, чем появится второй потребитель. Общий код без домена ждёт второго потребителя: связка ключей и политика запросов живут в `sapien-forge`, пока они нужны только ему.

Пакет собирается без сборки: `exports` указывает на `src/index.ts`, его компилируют Vite окна и Vitest. Классы Tailwind из пакета окно видит через `@source` в `styles.css`: без него стиль пропадает молча, без ошибки.

### Тест лежит рядом с проверяемым

Тест это `*.spec.ts` (`*.spec.tsx`, если в нём разметка) рядом с файлом. На интерфейсе основная масса входит через компонент пакета: настоящие слои, подмена только на границе процесса через `fakeRust`. Пакет в тесте собирается через дверь, а не из внутренностей: тогда перекладка файлов внутри пакета тесты не ломает. Изолированные тесты только у домена и у чистой модели интерфейса. Тест Rust живёт в `#[cfg(test)] mod tests` того же файла; сценарий проверяется на двойниках портов, команда через `tauri::test`. Крейт домена тестируется без Tauri: `cargo test -p sapien-<домен>`.

## Как добавить

Команду Rust: сценарий в `use_case` крейта домена; функция с `#[tauri::command]` и `#[specta::specta]` в `src-tauri/src/commands/<домен>.rs` с именем `<домен>_<действие>`, строка в `collect_commands!` в `bindings()` из `lib.rs` полным путём `commands::<домен>::команда`. Макрос ищет рядом с командой скрытые функции, которые переэкспорт через `pub use` не уносит, поэтому модули команд открыты из `commands/mod.rs` целиком. Типы аргументов и ответа выводят `specta::Type`. Дальше `cargo test -p sapien` переписывает `bindings.gen.ts`, а на интерфейсе вызов `commands.<команда>` в `interactions/` и строка в двери пакета. Событие окну: тип с `tauri_specta::Event` в `events.rs` и строка в `collect_events!`.

Домен: строка в таблице «Домены» и место в дереве этого документа, потом код. Список доменов `scripts/check-boundaries.mjs` берёт из папок `domains/` и `crates/`, его правка не нужна.

- Крейт: `crates/<домен>` по шаблону из дерева, `Cargo.toml` с версиями из `[workspace.dependencies]` и `[lints] workspace = true`, член workspace подхватывается сам по `crates/*`. Сервис собирается в корне композиции, команды в `src-tauri/src/commands/<домен>.rs`.
- Пакет: `domains/<домен>` по шаблону из дерева, `package.json` с `exports` на `src/index.ts`, `tsconfig.json` от `tsconfig.base.json`, свои `typecheck` и `test`. Зависимость `"@sapien/<домен>": "workspace:*"` у того, кто его ставит на страницу.
- Страница в `pages/` окна ставит компонент пакета.

Если шагов выходит больше, значит общее не доехало до общих пакетов или `sapien-kernel`.

## Отвергнутые варианты

Слои сверху, модули внутри (`layers/use-case/<сущность>`). Барель на каждом слое открывает любой сценарий любому файлу, а сущность размазывается по четырём каталогам. При модулях сверху дверь одна и её стережёт проверка границ.

Клиентский `use-case` на каждую команду. Половина сценариев была бы строкой «вызови Rust». Слой заведём, когда у сценария на интерфейсе появится что решать; пока эту роль несёт `interactions`.

Пакет на каждый слой (`@sapien/sessions-model`, `@sapien/sessions-components`). Пакетов стало бы вчетверо больше, хотя слои одного домена меняются вместе. Направление слоёв внутри пакета дешевле держит oxlint.

Плагин Tauri на домен. Это родной для Tauri способ делить команды, но имена стали бы `plugin:sapien-projects|list`, а каждому плагину нужен свой `build.rs` с манифестом прав. Главная польза плагинов, право на каждую команду, достижима и в приложении через `AppManifest`.

Каталог на домен с Rust и TypeScript внутри (`domains/forge/{rust,ts}`). Домены двух языков не совпадают один к одному: у `layout` нет крейта, а у блокировки, обновлений и вида Rust это файл приложения. А контракт всё равно один файл на всё приложение.

Домены модулями внутри окна (`apps/desktop/src/modules/<домен>`), как было до ноября 2026, или одним пакетом на все. Так устроен ad-tune, где у модулей одно приложение и границы держит скрипт. Отдельный пакет держит границу сам: у него свой `node_modules` без соседей, свой `tsc` и свой `test-setup.ts`, и соседа или чужую строку он не находит. В общем приложении всё это одно на всех, и каждую границу пришлось бы держать правилом линтера.

DI-контейнер в Rust или TypeScript. Сборка в корне занимает экран кода и видна целиком, а контейнер переносит ошибки сборки на время запуска.

Сервер-заготовка на будущее. До ноября 2026 рядом с окном жил `apps/api` на Hono с одним маршрутом `/health`, и его клиент не звал никто. Ради него окно держало hono, адрес в CSP и отдельный процесс в `pnpm dev`. Понадобится сервер, он вернётся из истории git.

Vue вместо React. React выбран в расчёте на приложение для телефона: Expo работает только на React Native, а у Vue аналога нет (Vue Native заброшен, NativeScript-Vue сильно меньше, остальные варианты это webview). Телефон отложен, но если он вернётся, его интерфейс напишется на том же языке, что и окно.

TanStack Start вместо голого React. Tauri раздаёт окну статические файлы, серверного рендеринга там нет.
