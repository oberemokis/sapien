# Интеграции

Что GitHub, GitLab и YouTrack отдают через API: каким токеном, в каких пределах запросов, какие сущности и какая история их изменений. Сведения сверены с документацией сервисов 6 ноября 2026 года. Цифры пределов сервисы меняют без предупреждения, поэтому перед задачей на интеграцию их стоит перепроверить по ссылкам в конце.

## Общее для всех трёх

Данные приходят опросом с устройства. Вебхуки всех трёх сервисов (у YouTrack это HTTP-запрос из workflow или приложения) шлют событие на публичный адрес, а своего сервера у приложения нет. Поэтому изменения видны, пока приложение открыто, а при открытии догоняются по полю «обновлено после»: `since` и `updated_after` у GitHub и GitLab, поисковый запрос `updated:` и курсор ленты у YouTrack.

Готовые отчёты сервисов (графики Projects у GitHub, value stream у GitLab, отчёты YouTrack) приложению почти не помогают: их либо нет в API, либо они на старших тарифах. Надёжная основа для аналитики это история изменений каждой задачи, и её отдают все трое бесплатно. Время цикла, пропускную способность, блокировки и разброс оценок приложение считает из неё само.

| | GitHub | GitLab | YouTrack |
| --- | --- | --- | --- |
| API | REST (версия `2026-03-10`) и GraphQL | REST v4 и GraphQL | REST, только нужные поля в `fields` |
| Токен для чтения | fine-grained, права «на чтение» по разделам | личный, область `read_api` | постоянный токен с областью YouTrack |
| Срок токена | задаёт человек | по умолчанию не больше 365 дней | бессрочный, пока его не отзовут |
| Предел запросов | 5 000 в час | 2 000 в минуту сейчас, по тарифу с 2027 года | для Cloud не опубликован |
| Страница | до 100 записей | 20 по умолчанию, курсор у задач | 42 по умолчанию, курсор у ленты |
| История задачи | timeline и события задачи | resource events по полям | лента активности по категориям |
| Свой сервер | GitHub Enterprise Server | Self-Managed | YouTrack Server |

## GitHub

### Доступ

GitHub советует fine-grained токен вместо классического. Ему нужны права на чтение:

| Право | Что открывает |
| --- | --- |
| Repository: Metadata | репозиторий, участники, языки, теги, события, статистика `stats/*` |
| Repository: Issues | задачи, подзадачи, связи «блокирует», комментарии, метки, вехи, timeline |
| Repository: Pull requests | пул-реквесты, их коммиты, файлы, ревью, запрошенные ревьюеры |
| Repository: Contents | коммиты, сравнение веток, ветки, релизы, файлы |
| Repository: Actions | запуски workflow, задания, время выполнения |
| Repository: Deployments | развёртывания и их статусы |
| Repository: Commit statuses | статусы проверок коммита |
| Organization: Projects | Projects организации: поля, элементы, представления |

Какое право нужно запросу, GitHub пишет в заголовке ответа `X-Accepted-GitHub-Permissions`.

### Пределы

- REST: 5 000 запросов в час на пользователя, без токена 60.
- GraphQL: 5 000 очков в час. Стоимость запроса это число запрошенных узлов, делённое на 100, но не меньше 1. У любой связи обязателен `first` или `last` от 1 до 100, в одном запросе не больше 500 000 узлов, запрос дольше 10 секунд обрывается.
- Вторичные пределы, общие для REST и GraphQL: не больше 100 запросов одновременно, 900 очков в минуту на REST и 2 000 на GraphQL (чтение стоит 1 очко, запись 5), не больше 80 записей в минуту и 500 в час.
- Списки REST отдают до 100 записей на страницу, по умолчанию 30.

### Данные

| Сущность | Что есть | Для аналитики |
| --- | --- | --- |
| Задача | заголовок, описание, состояние и причина закрытия, автор, исполнители, метки, веха, тип задачи организации, поля задачи (текст, выбор, число, дата), даты создания, изменения и закрытия | поток задач, распределение по людям и меткам |
| Пул-реквест | то же, что у задачи, плюс ветки, черновик, слияние, коммиты, файлы, ревью и их состояние | время до первого ревью, до слияния, размер изменений |
| Подзадачи | родитель и подзадачи, порядок | прогресс эпика по подзадачам |
| Связи | «блокирует» и «заблокирована», в задаче сводка `issue_dependencies_summary` | цепочки блокировок |
| История задачи | timeline: назначения, метки, вехи, переименования, ссылки из коммитов и пул-реквестов, закрытие и открытие | время в каждом состоянии, возвраты в работу |
| Коммиты | автор, дата, сообщение, сравнение веток | связь коммитов с задачами по ссылкам в сообщениях |
| Actions | запуски, задания, время выполнения | частота и длительность сборок, доля падений |
| Развёртывания | окружение, статусы с датами | частота выкладок, время от слияния до выкладки |
| Вехи и релизы | сроки, число открытых и закрытых задач | прогноз по сроку вехи |
| Projects | поля проекта (текст, число, дата, выбор, итерация), до 50 полей; элементы с их значениями | спринты через поле итерации, статус доски |
| Статистика репозитория | коммиты по неделям, по авторам, добавленные и удалённые строки | активность в коде |

Чего нет:

- Графики Projects (insights) в API не описаны. Нужное приложение строит само из элементов проекта.
- DORA-метрик GitHub не считает. Частоту выкладок и время от слияния до выкладки приложение получает из развёртываний и пул-реквестов.
- Статистика репозитория при первом запросе отвечает `202` и считается в фоне, ответ надо запросить ещё раз. При 10 000 коммитов и больше `code_frequency` отказывает, а `contributors` отдаёт нули в строках. Слияния статистика не считает.

## GitLab

### Доступ

Для чтения хватает личного токена с областью `read_api`: она открывает только `GET` и `HEAD`. Запись в задачи потребует `api`, а это полный доступ ко всему, что может пользователь. Токен по умолчанию живёт не больше 365 дней и истекает в полночь по UTC. На своём сервере срок задаёт администратор.

Возможности зависят от тарифа группы: Free, Premium, Ultimate. На своём сервере тариф даёт лицензия, а пределы задаёт администратор.

### Пределы

- Сейчас на gitlab.com: 2 000 запросов API в минуту на пользователя, поиск 100 в минуту, список проектов 2 000 за 10 минут.
- Пределы по тарифам объявлены, но ещё не действуют. Free: 5 000 в час и 100 в минуту. Premium и Ultimate с января 2027 года: 15 000 и 25 000 в час. Действует меньший из двух пределов, текущий или тарифный.
- Превышение отвечает `429` с заголовком `Retry-After`.
- Страница по умолчанию 20 записей. Задачи проекта листаются курсором, и GitLab советует его для последовательных страниц.

### Данные

| Сущность | Тариф | Что есть |
| --- | --- | --- |
| Задачи | Free | состояние, даты создания, изменения и закрытия, кто закрыл, исполнители, метки, веха, тип (задача, инцидент, тест-кейс, task), чек-лист в описании |
| Вес и итерация задачи | Premium | поля `weight` и `iteration`, фильтр по ним |
| Здоровье задачи | Ultimate | `health_status` |
| Связи задач | Free | «связана с» |
| Блокировки | Premium | «блокирует» и «заблокирована» |
| Эпики | Premium | REST эпиков помечен устаревшим, эпики переходят в work items GraphQL |
| Учёт времени | Free | оценка и затраченное время у задач, merge request и эпиков; записи времени через GraphQL `timelogs` |
| История задачи | Free | события состояния, меток и вех у задач и merge request (`resource_*_events`) |
| История итераций и веса | Premium | `resource_iteration_events`, `resource_weight_events` |
| Merge request | Free | ветки, коммиты, ревьюеры, обсуждения, слияние |
| Одобрения merge request | Free | кто одобрил; правила одобрения на Premium |
| Конвейеры и задания | Free | статус, время, длительность |
| Развёртывания и окружения | Free | окружение, статус, дата |
| Вехи | Free | сроки и задачи |
| Итерации | Premium | у группы, проект видит итерации своих групп |
| Доски | Free | колонки по меткам |
| Счётчики задач | Free | `issues_statistics`: только числа открытых и закрытых по фильтру |
| Аналитика вклада | Premium | события участников группы через GraphQL |
| Value stream analytics | Free с одним потоком, Premium для своих потоков | медиана и среднее по этапам через GraphQL |
| DORA | Ultimate | частота выкладок, время изменения, время восстановления, доля неудачных изменений |

Оговорки:

- История состояния не хранит создание задачи: у задачи, которую ни разу не закрывали, список пуст. Начало берётся из `created_at`.
- Если в группе Free, значительная часть планирования (вес, итерации, блокировки, эпики) недоступна. DORA приложение считает само из развёртываний и merge request, как на GitHub.
- GitLab сам переходит на work items: задачи, эпики, цели и ключевые результаты становятся одним типом в GraphQL. Новые интеграции лучше строить на нём.

## YouTrack

### Доступ

Постоянный токен создаётся в профиле и получает права своего пользователя в выбранной области. Запросы идут на `https://<хост>/api`, в Cloud и на своём сервере одинаково.

Ответ содержит только поля, перечисленные в параметре `fields`, иначе приходит лишь идентификатор. Это экономит трафик, но каждое новое поле в интерфейсе требует правки запроса.

### Пределы

Предел запросов для Cloud в документации не найден. Свой сервер ограничен только своей мощностью.

Коллекции без `$top` отдают не больше 42 записей. Задачи без `$top` ограничены настройкой «Max issues to export». Ленту активности листают курсором (`cursorAfter`, `cursorBefore`), потому что `$skip` сбивается, когда между запросами появляются новые события.

### Данные

| Сущность | Что есть |
| --- | --- |
| Задача | `idReadable` вида `SP-38`, сводка, описание, автор, кто менял, даты создания, изменения и решения (`resolved` пуст, пока задача не решена), теги, комментарии, вложения, черновик |
| Поля задачи | свои у каждого проекта. Состояние со знаком «решено» (`isResolved`), приоритет, исполнитель, оценка и затраченное время в минутах |
| Связи | типы связей настраиваются: подзадача и родитель, «зависит от», «дублирует», «связана с» и свои |
| Доски и спринты | доска со своими проектами, полем оценки, колонками и текущим спринтом; спринт с целью, началом, концом, задачами, числом нерешённых и архивом |
| Учёт времени | записи работы: кто, когда, сколько минут, тип работы; фильтр по датам, автору и поисковому запросу |
| Изменения кода | коммиты и пул-реквесты, привязанные к задаче через интеграцию YouTrack с GitHub, GitLab, Bitbucket и CI |
| Сохранённые запросы | поиски пользователя, их можно брать источником задач |
| Лента активности | по категориям: создание, решение, поле, связь, спринт, сводка, описание, теги, комментарии, вложения, изменения кода и пул-реквесты; у каждой записи автор, время, что убрано и что добавлено |

Чего нет:

- Отчётов (диаграмма сгорания, накопительный поток, отчёты по времени) в REST нет, их надо считать из ленты и записей работы.
- Категории для записей работы в ленте нет, их берут отдельно из `/api/workItems`.
- Поля задачи у каждого проекта свои, и состояние «в работе» в разных проектах называется по-разному. Приложению придётся спросить у человека, какие состояния что значат, или вывести это из `isResolved` и порядка состояний.

У YouTrack есть свой MCP-сервер для ИИ-агентов. Хватит ли его для публикации пачки задач со связями, не проверено: с REST это точно получается.

## Что считается для аналитики

| Метрика | GitHub | GitLab | YouTrack |
| --- | --- | --- | --- |
| Время цикла задачи | timeline: назначение, метки, закрытие | события состояния и меток | лента: поле «Состояние», решение |
| Пропускная способность | закрытые за период | `closed_at`, `issues_statistics` | `resolved` |
| Незавершённая работа | открытые с исполнителем или в колонке Projects | открытые по меткам доски | нерешённые в спринте |
| Блокировки | `blocked_by`, `blocking` | Premium: блокирующие связи | связи «зависит от» |
| Оценка и факт | поле Projects (число), факта нет | вес на Premium, учёт времени на Free | оценка и записи работы |
| Время ревью | ревью пул-реквеста | ревьюеры и одобрения | пул-реквесты из интеграции с кодом |
| Выкладки | развёртывания | развёртывания, DORA на Ultimate | нет, только через GitHub или GitLab |
| Спринты | поле итерации Projects | итерации на Premium | спринты досок |

## Что не проверено

- Отдаёт ли timeline GitHub смену статуса элемента в Projects, не проверено. Если нет, время на доске придётся считать по снимкам при опросе.
- Linear не исследован: его API и пределы опишет отдельная задача.
- Предел запросов YouTrack Cloud и число элементов в одном Projects GitHub в документации не найдены.
- Какие виджеты work items GitLab (иерархия, связи, вес, статус) на каком тарифе, не сверено по справочнику GraphQL.
- Ничего из этого не проверено живым запросом: цифры взяты из документации.
